# OA 系统实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**目标：** 为单一组织交付可容器部署的 OA 首期版本，包含可配置工作流、编制表、自动复核和现有企业邮箱接入。

**架构：** Rust workspace 模块化单体，API 与 worker 共用领域和应用层；PostgreSQL 为唯一业务事实来源，Redis 仅用于缓存及短时提示；React + TypeScript + Ant Design 提供 UI。流程版本不可变，节点由注册表扩展，跨系统工作通过 PostgreSQL outbox 重试。

**技术栈：** Rust stable、Tokio、Axum、SQLx、PostgreSQL、Redis、React、TypeScript、Ant Design、Docker、Docker Compose、pnpm。

**设计说明：** docs/superpowers/specs/2026-11-19-oa-system-design.md

## 全局约束

- 首期单一组织；所有 API 均执行服务端组织范围授权。
- Rust 用于后端和 worker；浏览器使用 React + TypeScript + Ant Design。
- PostgreSQL 是流程、任务、复核和邮箱同步的权威数据源；Redis 不承担业务队列或状态真相。
- 已发布流程与表单 schema 不可改写，实例记录版本和输入快照。
- 只配置已注册节点，不执行用户任意代码。
- 上报、复核实例、初始任务和 outbox 在一个 PostgreSQL 事务中创建。
- 可重试写操作使用幂等键或唯一约束。
- 支持 Docker Compose，不提交真实凭据；邮箱与依赖版本在阶段 0/初始化时确认锁定。

## 文件与模块结构

- apps/server：Axum API 与 api、worker 启动入口。
- crates/domain：无 I/O 实体、状态机、值对象和领域错误。
- crates/application：用例、授权策略及端口 trait。
- crates/infrastructure：SQLx/PostgreSQL、Redis、文件存储和 outbox 实现。
- crates/email-connectors：供应商邮箱适配器。
- migrations：有序 SQL 迁移。
- web：React + TypeScript + Ant Design。
- deploy：多阶段 Dockerfile、Compose 环境配置和运维脚本。
- docs/superpowers/specs 与 docs/superpowers/plans：设计与实施计划。
