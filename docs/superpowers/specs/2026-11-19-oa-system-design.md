# OA 系统架构设计

**日期：** 2026-11-19
**状态：** 总体方向已确认；邮箱与部署细节在第 0 阶段验证。

## 1. 目标与前提

建设面向单一组织的 OA 系统，包含工作台、可配置流程、可扩展业务系统和现有企业邮箱接入。后端及后台任务使用 Rust；浏览器 UI 使用 React + TypeScript + Ant Design。系统必须支持容器化部署。

- 首期仅支持单一组织，不建设多租户隔离。
- 邮箱接入已有企业邮箱，厂商和协议待确认。
- 管理员可配置流程定义、可用流程节点和编制表字段。
- 向上级部门上报时自动创建对应复核流程。
- 首期使用模块化单体和 Docker Compose，不要求 Kubernetes。

## 2. 架构决策

### 2.1 模块化单体

采用 Rust workspace 模块化单体：同一 server 二进制提供 API 与 worker 两种运行模式，共享领域、应用服务和基础设施模块。前端独立构建；PostgreSQL、Redis 和附件存储作为有明确持久化策略的依赖服务。

这样，上报、复核实例、初始任务与 outbox 事件能在 PostgreSQL 的单一事务中创建。若团队、负载或独立发布需求增长，再评估拆分邮箱同步等服务。

### 2.2 技术栈

- Rust stable、Tokio、Axum：API 和异步后台任务。
- SQLx、PostgreSQL：显式 SQL、版本化迁移与事务。
- Redis：短期缓存、可选会话和实时刷新提示。
- React、TypeScript、Ant Design：中文管理端与工作台。
- Docker 多阶段构建、Docker Compose：开发与首期部署。
- 项目初始化时核对并锁定依赖版本，提交 Rust 和前端 lockfile。

Ant Design 是 React 组件库，因此浏览器端采用 React + TypeScript，Rust 用于服务端。若前端也必须使用 Rust，应重新评估 UI 选择。

## 3. 模块边界

- **身份与组织**：用户、部门树、岗位、人员状态、角色和组织范围授权。
- **编制与表单**：编制表定义、字段元数据、人员占岗关系、表单版本和扩展数据。
- **流程定义**：草稿、发布版本、节点类型目录、节点配置、连线和条件。
- **流程运行时**：实例、节点实例、用户任务、表态、总结、上报、交付和审计。
- **复核**：上报来源、复核模板映射、复核实例、来源唯一性及完成闭环。
- **企业邮箱**：账户映射、供应商连接器、同步游标、邮件索引、发送状态和附件引用。
- **工作台**：待办、已发起、已处理、未读邮件、通知和快捷入口。
- **平台运维**：配置、健康检查、日志、迁移、备份、恢复和容器部署。

模块通过应用服务接口协作，不直接写入其他模块的私有表。

## 4. 流程定义与节点

流程定义使用经过校验的有向无环图。定义包含多个版本；草稿可修改，发布版本不可变，实例固定引用启动时的发布版本。版本、节点、边、状态与审计保存于关系表；节点扩展配置保存为经类型 schema 验证的 JSONB。

管理员从节点目录选择已注册类型并配置属性、表单、人员规则及条件。自定义指通过配置组合已注册能力，不执行任意 Rust、SQL、JavaScript 或其他用户脚本。新增全新行为需开发并注册 Rust 节点处理器。

每个节点类型提供稳定类型标识、配置 schema、发布期校验器和运行处理器。首期运行图支持顺序、条件分支、并行扇出和“全部完成”汇合；复杂 N-of-M 投票、循环、定时脚本和任意代码节点不在首发范围。

- **表态节点**：按部门、岗位、角色和在编状态匹配有效人员，支持一人或多人。首期支持轮转、当前待办数最少优先；平局按用户 ID 稳定排序。激活时保存受派人快照；无人合格时明确报错并阻止继续。
- **总结节点**：由有权处理人手动总结，关联并快照引用的表态内容，记录作者、时间和修改审计。
- **上报节点**：只能选择有效上级部门。未配置目标部门对应的复核模板时禁止提交。上报记录、复核实例、初始任务和 outbox 事件在同一 PostgreSQL 事务内创建。
- **交付节点**：记录说明、接收部门/人员、附件引用、交付时间与确认状态；重复请求不重复创建交付。

每次动作校验用户授权、任务状态、流程版本和幂等键。事务内锁定实例及活动节点、写动作和审计、激活后继节点、写 outbox。外部网络请求不放入数据库事务；唯一约束和条件更新防止重复上报及并发双提交。

## 5. 组织、编制与数据库约束

人员、部门、岗位、编制槽位、占岗关系、状态、流程、任务和同步游标等核心信息使用具名关系表、外键与约束。自定义编制列使用版本化字段元数据和 JSONB 扩展值；高频检索字段保持类型化，只为已验证的查询需求创建扩展字段索引。

表单 schema 发布后保留版本；流程实例保存定义版本及提交快照。审批动作、授权变更和管理员操作写审计日志。数据库访问使用参数化 SQL、明确事务边界、连接池上限及按查询设计的索引。服务端对每次请求强制执行组织范围授权。Redis 只承担带 TTL 的缓存与短时提示；清空 Redis 不得改变待办或流程状态事实。

## 6. 企业邮箱接入

阶段 0 确认邮箱厂商、可用 API/IMAP/SMTP、OAuth 或应用凭据、邮件同步范围、共享邮箱、发件身份、限流与附件限制。适配器隔离供应商 SDK，应用层不依赖具体厂商。

后台 worker 持久化同步游标、供应商邮件 ID 和发送状态；按邮件 ID 去重，失败可退避重试。PostgreSQL outbox 是任务来源，Redis Pub/Sub 只提示界面刷新。发送超时但结果不确定时显示“待核实”，避免重复发件，除非供应商支持可验证的幂等发送。

凭据经受控 secret 配置注入，不存业务表明文或写入日志。附件使用可替换的存储接口，首期可用纳入备份的持久卷。邮件和附件都执行服务端授权。邮件正文、令牌、密码和敏感附件内容不写入日志。

## 7. UI 交互

使用 Ant Design 的 Layout、Menu、Table、Form、Drawer、TreeSelect、Steps/Timeline、Tag、Modal 和 ConfigProvider 中文 locale。工作台突出待办和未读；流程设计器包含节点清单、画布、属性面板和发布校验；流程详情显示节点时间线、当前处理人、上报去向、总结与交付。

支持键盘操作、明确的空状态、字段校验、危险操作确认、加载及重试状态，并提供窄屏可用的只读视图。普通用户业务状态与管理员运维信息分开呈现。

## 8. 容器化与运维

Compose 服务包含 web、api、worker、postgres、redis。API 与 worker 使用同一 server 镜像和不同启动参数；迁移作为显式的一次性部署步骤。生产配置不将数据库或 Redis 端口暴露到公网，秘密从受控环境配置注入。

PostgreSQL 使用持久卷并制定备份、保留及恢复演练；附件卷一并备份。Redis 只存可重建缓存和短时数据。API/worker 提供 liveness 和 readiness 检查，数据库迁移完成后再开放流量。首期不声称 Compose 提供跨主机高可用；Kubernetes 和集中对象存储后续评估。

## 9. 首期验收标准

1. 管理员能创建、校验、发布和版本化流程；既有实例不会随草稿变化。
2. 表态节点只分配给符合在编和组织规则的人员，并保存受派快照；空候选集明确失败。
3. 总结节点保存人工总结、作者、时间和引用的表态。
4. 上报仅允许有效上级部门；成功上报原子创建一个复核实例和初始任务，重试不会重复。
5. 交付支持附件、确认和幂等保护。
6. 编制表支持自定义字段及 schema 校验，核心字段可查询，API 强制执行访问授权。
7. 邮件同步可续传且去重；不确定的发件结果显示待核实。
8. 重启容器后 PostgreSQL 数据和附件仍在；清空 Redis 不丢流程事实；备份能够恢复。
9. 自动化测试覆盖状态转换、越权拒绝、并发/重复提交、复核事务回滚和邮件同步去重。

## 10. 阶段 0 待确认项

邮箱厂商与协议、OAuth/应用凭据方式、同步范围与共享邮箱、邮件正文全文搜索、SSO、部门负责人来源、编制表必需字段、附件保留期限、用户规模、服务器资源和备份窗口。建议首期支持组织邮箱和共享邮箱，完成收件同步、发件、未读及基本搜索，不迁移全部历史个人邮件。
